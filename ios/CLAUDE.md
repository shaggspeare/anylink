# AnyLink for iOS

Native SwiftUI client for **AnyLink**, a personal library for saved links: *"Paste anything. We read the rest."*
This folder (`ios/`) holds the iOS app. The backend is the AnyLink web app in the parent folder (`../src`, Next.js +
Supabase Postgres). Its API is documented in `docs/05-data-and-api.md` §2 and `../docs/ios/03-api.md`. When the
contract is unclear, read the backend code: `../src/lib/db/actions.ts`, `../src/lib/db/queries.ts`, `../src/lib/types.ts`.
Don't change backend code from an iOS phase; leave a `// BACKEND:` note instead.

## Read before you write code

1. `docs/README.md`: map of the docs.
2. `docs/08-build-plan.md`: the phases. **Work one phase per session, in order.**
3. The doc the phase points to (screens, design system, API…).
4. `docs/spec/`: the original product specs (tokens + features). They are the source of truth for values, copy and
   behaviour. Where `docs/` and `docs/spec/` disagree, `docs/` wins, because it records later decisions (`docs/10-decisions.md`).
   Mention any conflict you find in your summary.

## Stack

- **iOS 26.0+**, iPhone first (iPad is a later phase). Xcode 26, **Swift 6 language mode, strict concurrency = complete**.
- SwiftUI + Observation (`@Observable`). No Combine. UIKit only where a doc says so
  (`UITextView` for highlights, `SFSafariViewController`, `UIPasteboard` pattern detection, the share extension host).
- SwiftData for the offline cache · Swift Charts · TipKit · App Intents · Core Spotlight.
- Third-party packages: **`supabase-swift` (auth only)**. Ask before adding anything else.
- The Xcode project is generated by **XcodeGen** from `project.yml` (template in `templates/project.yml`).
  Never hand-edit `AnyLink.xcodeproj`; edit `project.yml` and run `xcodegen generate`.

## Commands

```bash
xcodegen generate                                             # after any project.yml change
swift test --package-path Packages/AnyLinkKit                 # after every package change
xcodebuild -scheme AnyLink -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
xcodebuild -scheme AnyLink -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test   # UI tests, at phase gates
```

If the named simulator doesn't exist, run `xcrun simctl list devices available` and use the newest iPhone.

`swift test` runs the package on macOS, so keep it building there:

- Wrap UIKit-only code (`UIColor`, `UIPasteboard`, `UIFont` registration) in `#if canImport(UIKit)`.
- If a module genuinely can't build for macOS, run the package tests on the simulator instead:
  `xcodebuild test -scheme AnyLinkKit-Package -destination 'platform=iOS Simulator,name=iPhone 17 Pro'`.

## Rules

1. **Tokens only.** Colours, sizes, radii, fonts, shadows and motion come from `AL` (`DesignSystem/Tokens.swift`).
   A hex value, magic number or `.font(.system(size:))` inside a screen view is a bug.
2. **Copy is specified.** Use the strings in `docs/04-screens.md` exactly. Put them in `Localizable.xcstrings`
   (English only for now). The voice is short, plain and second person, and explains consequences without blaming.
3. **Views don't do I/O.** Screens read from `LibraryStore` (or a screen model) and call its intents. Only
   `Networking` talks to the network; only `Persistence` touches SwiftData.
4. **Product principles are tested behaviour** (`docs/01-product.md`):
   - Capture never blocks.
   - Nothing is deleted outright: Trash plus a 5 s Undo.
   - The user's edits beat the AI.
   - States are reported honestly ("excerpt only", "title guessed").
   - Dead means gone, not refused.
   - One query language everywhere.
5. **Liquid Glass only on floating controls**: tab bar, toolbars, the paste accessory, floating buttons.
   - Content (cards, rows, panels, the article) uses the `Frosted` modifier.
   - Never put glass on glass.
   - Under Reduce Transparency, every frosted surface turns into solid `AL.paper`.
6. **Accessibility is part of done.**
   - Dynamic Type through `relativeTo:`.
   - An `accessibilityLabel` on every icon-only control.
   - Combined elements on tiles and rows, plus rotor actions.
   - 44 pt minimum hit targets.
   - Reduce Motion: no entrance springs.
7. **Every view has `#Preview`s** in light and dark, fed by `Fixtures`. Previews must not hit the network.
8. **Don't invent backend behaviour.**
   - If an endpoint is missing (see `docs/05-data-and-api.md` § Gaps), implement against `MockAPI`.
   - Mark the call site with `// BACKEND: <what is needed>`.
9. **Swift style.**
   - Value types for models; `@MainActor` for UI state; actors for shared mutable services.
   - No force unwraps outside tests.
   - `async/await` everywhere; no completion handlers in new code.

## Definition of done (every task)

- Builds with **zero warnings**; `swift test` passes; new logic has tests.
- Each screen shows every state listed for it in `docs/04-screens.md`, in previews and in the running app.
- Light and dark mode checked. VoiceOver labels present. Largest Dynamic Type size doesn't clip.
- Summary at the end: what changed, what's left, spec conflicts found, `// BACKEND:` items added.

## Working style

- At the start of a phase: read it, restate the task list, then implement task by task.
- Commit after each task: `phase-4: library tiles grid`.
- Ask before you add a dependency, change the data model or API contract, or depart from a screen spec.
- When unsure about a visual detail, check the reference prototype (link in `docs/README.md`) and the spec
  before guessing.
